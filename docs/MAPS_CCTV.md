# 실제 지도와 공공 CCTV — 2026-10-09

추가 고도화: 서버 상시 감시·보정 위치 추정·자동 확산 연계는 [CCTV_MONITORING.md](CCTV_MONITORING.md)를 우선 참고하세요. 아래는 최초 지도/브라우저 CCTV 통합 시점의 기록입니다. 현재 상시 감시 코드는 추가됐지만 기관 허용 미확인으로 실제 공공 영상 수집은 OFF입니다.

현재 UTIC는 사용자 신청 완료·승인 대기이며 미연결이다. 승인 전 재신청·목록 크롤링·IP 우회는 하지 않는다. 승인 후 키와 등록된 공인 IP, AI 분석·증거 저장 허용 목적을 확인하여 별도 어댑터로 연계한다.

## 화면

- `확산 시뮬레이션`: 네이버 위성·도로 / 일반지도 전환, 임상도·지형 격자 선택, 발화점 클릭, 주소 검색·좌표 주소 확인.
- `로컬 GIS · PNG 내보내기`: 기존 외부 배경 없는 GIS 렌더러와 PNG 내보내기 보존. 네이버 타일은 수집·캡처·재배포하지 않음.
- `공공 CCTV`: 대구 주변 고속도로·국도와 영상 형식을 사용자가 선택 조회. 목록·지도에서 한 지점 선택 후 재생.
- 권한 확인 체크 후 프레임 AI 분석: 최대 2분, 약 1.5초 + 추론 시간 간격, 요청 중첩 없음. 페이지 이동·숨김·오류 시 중지. 원본 영상 녹화 없음. 기존 지속 후보 게이트를 통과하면 웹 알람·증거 이미지 저장.

## 서버 설정과 보안

루트 `.env`의 `NAVER_MAPS_CLIENT_ID`, `NAVER_MAPS_CLIENT_SECRET`, `ITS_API_KEY` 사용. 네이버 JS SDK ID는 브라우저 공개 식별자이며 Secret은 서버 요청 헤더에만 사용. `VITE_`에 Secret을 넣지 않는다. Drive TXT는 암호화 저장소가 아니므로 공유 권한 제한과 향후 안전한 비밀 관리가 필요하다. 가져오기는 원본 TXT를 변경하지 않고 이전 env를 무시되는 runtime 아래 보존한다.

새 네이버 REST 호스트는 `https://maps.apigw.ntruss.com`. JS는 `https://oapi.map.naver.com/openapi/v3/maps.js?ncpKeyId=...`. NCloud 등록 Web URL에는 PC `http://localhost:5173`, 실제 사용할 휴대폰 HTTPS origin과 배포 origin을 각각 등록해야 한다. 인증 실패 시 임의 우회하지 않고 로컬 GIS로 전환한다. 무료 사용량·청구·일별 한도는 콘솔에서 확인한다.

서버는 고정 공식 API만 요청한다. 사용자 입력 URL을 서버에서 다운로드하거나 영상 프록시로 가져오지 않는다. 카탈로그는 128.35–128.85E, 35.60–36.10N 사각 범위에 제한하며 대구 행정구역과 동일하지 않다. 목록 캐시는 24시간, 갱신/실패 재시도 최소 60초. 영상 URL은 선택 시 인증 사용자에게만 제공하며 ITS 앱 키는 브라우저로 전달하지 않는다. 제공기관 URL의 수명·CORS·서비스 중단은 별도 제약이다.

## 제한

브라우저 CORS가 허용되지 않으면 재생이나 캔버스 추출이 실패할 수 있다. 이를 모델 결과로 위장하지 않는다. 기관 승인 없는 프록시·우회·대량 크롤링을 하지 않는다. 지속적인 서버/edge 수집은 제공기관에 AI 분석·증거 저장·재표출·보존 기간을 확인한 후 별도 설계한다. 현재 선택된 스트림의 CORS 허용 여부에 의존하며 무인 24시간 관제 기능은 아니다. 공공 도로 CCTV 연결은 산불 환경 성능 검증을 대체하지 않는다.

CCTV 설치 좌표는 실제 발화 좌표가 아니다. 위성사진은 실시간 영상이 아니며 지도 개선은 90m DEM 또는 확산 계산의 정확도 향상을 뜻하지 않는다. 확산 계산 가능 범위는 기존의 일부 숲 격자에 한정된다. 10/30/60 모델분·반복 비율은 실제 도달시각·산불 확률이 아니다.

## 추가 영상 경로

1. ITS 국가교통정보센터: 고속도로·국도 영상 API, 현재 통합 대상. https://www.its.go.kr/opendata/opendataList?service=cctv
2. UTIC: 도시 도로 CCTV. 별도 키·IP 인증과 신청 목적 확인. 기존 ITS 키로 대체 불가. 공식 공지의 과접속 제한 준수. https://www.utic.go.kr/guide/utisRefCctv.do
3. 대구교통종합정보: 지역 CCTV 열람. 연구용 API·AI 재사용은 운영기관 문의 후 연계. 웹페이지 내부 URL 크롤링은 하지 않음. https://car.daegu.go.kr/
4. 산불 감시 CCTV: 산림청·대구시/구군 산림 담당 부서에 대학 연구용 영상 제공·분석 승인 문의. 공개 설치 위치 목록은 영상 API가 아님.
5. 휴대폰/팀 소유 IP 카메라: 동의·권한을 확보한 자체 영상이 지속 테스트에는 가장 통제 가능하다.

## 이번 검증 결과

- 저장된 실제 키로 네이버 주소 검색 `OK` 1건, 좌표 주소 변환 코드 0·2건 응답 확인.
- ITS `ex`, `cctvType=4` 대구 주변 목록 216건 응답 확인. 모든 지점의 재생 성공을 뜻하지 않음.
- 실제 로그인 화면에서 위성·일반지도 전환과 기존 저장 CA 결과의 불꽃 마커·주황색 영역 중첩을 시각 확인. 45.12ha는 이전 시나리오의 모의 면적이지 새로 검증된 실제 피해 면적이 아님.
- `[경부선] 안심` HTTPS HLS 영상이 브라우저에서 720×480, 재생 시간 증가·오류 없음으로 확인됨. 분석 동의는 사용자가 직접 하도록 남김. 다른 지점·브라우저·휴대폰 재생은 별도 검증 필요.
- 실제 YOLO 모델을 사용한 임시 DB 테스트에서 새 ITS 프레임 경로 → 지속 후보 → 알람 → 증거 저장 검증. 공공 CCTV 영상의 산불 정확도 평가를 뜻하지 않음.
- 최종 자동 테스트: 백엔드 57개(실제 모델 포함), 프론트엔드 21개 통과, 빌드 성공, 운영 npm audit 0건. 기존 deprecation 경고와 대용량 지도/HLS 청크 빌드 경고는 남아 있음.
- Docker/AWS 실행·공개 배포, UTIC, 물리 Android/iPhone HTTPS 지도·영상은 이번에 실행하지 않음.

화면 확인 자료는 무시되는 `runtime/public/ember-map-20261009.jpg`, `runtime/public/ember-cctv-20261009.jpg`에 있다. 개발 검증용 화면이며 외부 지도 타일 수집·재배포 기능을 제공하는 것이 아니다. 원본 공공 영상의 AI 분석 동의는 대신 체크하지 않았다.
