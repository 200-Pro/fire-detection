# 휴대폰 카메라 사용

## PC에서 먼저

`http://localhost:5173`에서 로그인하세요. 기본 계정을 아직 바꾸지 않았다면 `admin / fire-demo-local`입니다. **시스템 설정 → 계정 보안**에서 자신만 아는 16자 이상 비밀번호로 먼저 바꾸세요. 비밀번호는 다른 사람이나 assistant에게 보내지 마세요. 변경 뒤에는 새 비밀번호를 사용합니다. PC에 웹캠이 없어도 `예제 테스트`는 가능합니다.

## 휴대폰은 HTTPS 주소가 필요

휴대폰의 `localhost`는 휴대폰 자기 자신입니다. PC의 localhost 링크/QR을 그대로 휴대폰에서 열면 안 됩니다. 같은 Wi-Fi의 `http://PC-IP:5173`도 카메라 secure context 조건을 충족하지 않습니다.

현재 준비한 LAN 주소는 **https://192.168.0.6:8443/camera**입니다. PC는 유선 연결이어도 같은 공유기에 연결되어 있으면 됩니다. 휴대폰 두 대는 같은 Wi-Fi에 연결하고, 게스트 Wi-Fi의 기기 격리 여부를 확인하세요.

- 공식 Caddy v2.11.7 ZIP을 배포처의 SHA512 체크섬과 비교해 검증했습니다. 모든 도구·CA·인증서·로그는 `D:\fire-dettection` 안에 있습니다.
- Caddy는 `192.168.0.6:8443`에만 바인딩됩니다. API 8000과 개발 서버 5173은 PC loopback에만 열립니다. 휴대폰에는 개발 서버 대신 빌드된 React 파일을 전달합니다.
- 인증서 발급과 CA·IP 이름을 검증하는 HTTPS health 연결은 완료했습니다. `verify=False`나 브라우저 보안 경고 우회는 사용하지 않았습니다.
- `skip_install_trust`로 PC/휴대폰의 인증서 신뢰를 자동 변경하지 않았습니다. AWS, 외부 터널, 공유기 포트 포워딩은 만들지 않았습니다.
- PC 관제 화면은 개발 모드에서만 `http://localhost:5173`을 함께 사용할 수 있습니다. 휴대폰 연결 코드/QR은 HTTPS 주소를 사용합니다. production에서는 이 localhost Origin 예외를 허용하지 않습니다.

## 인증서 등록 — 사용자가 직접

로컬 CA를 신뢰하면 이 CA가 서명한 인증서를 기기가 신뢰하게 됩니다. 단순한 파일 열기가 아니라 **보안 신뢰 설정 변경**입니다. 개인 테스트 기기에서만 사용하고, 조직 관리 기기는 관리자 승인 없이 변경하지 마세요. 테스트 후 이 CA만 제거하세요.

전달할 공개 인증서: **`D:\fire-dettection\runtime\public\ember-local-ca.cer`**. Android에서 PEM 파일을 요구하면 같은 폴더의 `.crt` 파일을 사용합니다. 자신의 USB/파일 전달 경로로 공개 인증서만 휴대폰에 옮기세요. **`runtime/caddy` 전체나 `.key` 파일은 전달하지 마세요.**

발급자/대상 이름: `Ember LAN Test Root CA`. 현재 인증서 SHA256 지문:

```text
DBA435275543969AFA0A5875EB7141B538E70CD5A033217C2E255A3AAB1077A3
```

기기에서 표시되는 인증서와 `runtime/public/lan-setup.json`의 지문을 대조합니다. CA 폴더를 지우거나 새로 발급하면 지문이 달라지므로 이전 값을 재사용하지 마세요.

### Android / Chrome

1. 공개 인증서 파일을 휴대폰에 저장합니다.
2. 설정에서 `인증서 설치` 또는 `CA 인증서`를 찾습니다. 일반적으로 `보안 및 개인정보 보호 → 기타 보안 설정 → 암호화 및 사용자 인증 정보` 아래에 있습니다. 제조사·버전에 따라 이름이 다릅니다.
3. HTTPS 사이트 신뢰를 위한 **CA 인증서**로 파일을 선택하고 내용을 확인합니다. Wi-Fi 인증서/사용자 개인 인증서와 혼동하지 마세요. 기기의 PIN 확인과 승인 단계는 직접 진행합니다.
4. Chrome을 다시 열고 HTTPS 주소에 보안 경고가 없는지 확인합니다. 경고가 남으면 진행하지 말고 화면을 공유해 원인을 확인하세요. 회사/학교 기기의 인증서 설치 제한은 우회하지 않습니다.

설정 경로와 인증서 관리의 일반적인 설명: [Google 공식 인증서 안내](https://support.google.com/pixelphone/answer/2844832?hl=ko). 이 페이지의 Wi-Fi 인증서 설치 절차와 웹 TLS용 CA 선택은 구분해야 합니다.

### iPhone / Safari

1. 공개 `.cer` 파일을 iPhone에서 열어 인증서 프로파일을 준비합니다. 선택한 파일 전달 방식에 따라 표시가 다를 수 있습니다.
2. `설정 → 일반 → VPN 및 기기 관리`에서 해당 프로파일의 발급자를 확인하고 직접 설치합니다. 기기의 암호 입력은 직접 합니다.
3. `설정 → 일반 → 정보 → 인증서 신뢰 설정`에서 **Ember LAN Test Root CA**의 SSL/TLS 신뢰를 직접 켭니다. 설치만 하고 신뢰를 켜지 않으면 HTTPS 연결에 사용되지 않습니다. [Apple 공식 설명](https://support.apple.com/en-us/102390).
4. Safari로 HTTPS 주소를 열어 보안 경고가 없는지 확인합니다. 카카오톡 등 앱 내 브라우저 대신 Safari를 사용하세요.

## Windows 방화벽

현재 PC의 이더넷 네트워크는 `공용`으로 분류돼 있습니다. 분류를 자동 변경하지 않습니다. 사용자 승인 후 **해당 Caddy 실행 파일 + TCP 8443 + 이더넷 + PC 주소 192.168.0.6 + 같은 서브넷 192.168.0.0/24**만 허용하는 규칙을 사용할 수 있습니다. 전역 방화벽 끄기나 모든 포트 허용은 하지 마세요. 승인/적용 여부는 `VERIFICATION.md`를 확인합니다. 관리자 권한이 필요한 경우 사용자가 직접 수행해야 합니다.

접속 시간 초과는 인증서 문제와 다릅니다. 같은 Wi-Fi인지, 기기 격리 여부, PC 절전, 방화벽 허용을 순서대로 확인합니다.

## 서버를 다시 켜는 명령

```powershell
Set-Location "D:\fire-dettection"
& ".\scripts\start-local.ps1" -LanAddress "192.168.0.6"
```

종료는 `& ".\scripts\stop-local.ps1"`입니다. DB·증거 사진·CA는 보존합니다. IP가 바뀌면 실제 PC의 사설 IP로 시작하고 새 QR을 발급하세요. Wi-Fi 연결용 공유기 포트 포워딩은 필요하지 않습니다.

## 연결 후

1. PC 관리자 화면에서 `안드로이드 테스트`, `아이폰 테스트` 카메라를 각각 등록하고 별도 연결 코드를 발급합니다. 코드를 두 휴대폰에 같이 쓰지 마세요.
2. 휴대폰에서 HTTPS `/camera` 페이지를 열고 코드를 입력합니다. 코드는 10분 유효·일회용입니다.
3. 후면/전면을 고르고 `전송 시작`을 누릅니다.
4. 휴대폰 브라우저의 카메라 권한은 사용자가 직접 승인합니다. 마이크 권한은 요청하지 않습니다.
5. 약 1초 간격 프레임과 감지 결과를 확인합니다. PC 관제 화면에서 알람을 확인합니다.
6. `일시 중지`는 카메라 트랙을 닫습니다. `연결 해제`는 전송 키도 폐기합니다. 해제 후에는 새 코드를 발급하세요.

화면 잠금·다른 탭·백그라운드 이동 시 전송을 일시 중지합니다. 전용 앱처럼 백그라운드에서 계속 촬영하지 않습니다. 웹 창이 닫힌 상태에서 알람을 받으려면 추후 Web Push/PWA 또는 별도 앱이 필요합니다.

참고: [MDN getUserMedia 보안 조건](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).

## 두 기기 실측 체크리스트 — 아직 사용자가 실행해야 함

- [ ] Android: HTTPS 경고 없음 → 연결 → 후면 촬영 → PC 프리뷰/프레임 수 증가.
- [ ] iPhone: HTTPS 경고 없음 → 연결 → 후면 촬영 → PC 프리뷰/프레임 수 증가.
- [ ] 두 대 동시 전송, 전면 전환, 중지/재시작, 연결 해제 후 이전 키 무효 확인.
- [ ] 화면 잠금/다른 앱 이동 → 전송 일시 중지, PC에서 약 12초 뒤 오프라인 확인.
- [ ] 안전한 불꽃 이미지 또는 화면으로 후보 알람 → 증거 확인 → 확인 처리/종료.
- [ ] 불꽃 없는 방/조명에서 잘못된 경보 관찰. 실제 불을 만들지 않기.
- [ ] 테스트 후 해당 CA/프로파일만 제거하고, 필요 없는 방화벽 규칙 중지/제거.
