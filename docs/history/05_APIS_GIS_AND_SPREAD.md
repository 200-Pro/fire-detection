## 설정과 비밀정보

서버 루트 `.env`의 변수 이름은 `KMA_SERVICE_KEY`, `NIFOS_SERVICE_KEY`, `ITS_API_KEY`, `NAVER_MAPS_CLIENT_ID`, `NAVER_MAPS_CLIENT_SECRET`이다. 실제 값은 문서·GitHub·채팅·VITE 변수에 넣지 않는다. `.env`나 Drive TXT는 평문이므로 `.gitignore`만으로 안전한 비밀 저장소가 되는 것은 아니다. 배포에서는 별도 secret 관리·접근통제·회전이 필요하다.

Naver JS Client ID는 브라우저 식별자이고 Secret은 서버 REST 헤더 전용이다. Web URL에는 실제 localhost·LAN HTTPS·배포 origin을 등록해야 한다. Dynamic Map과 Geocoding/Reverse Geocoding을 선택했다. Static Map이나 Directions는 현재 확산 계산에 사용하지 않는다.

## 기상·위험 API 연결

기상청 [단기예보 서비스 안내](https://www.data.go.kr/data/15084084/openapi.do)의 초단기실황을 호출하는 구조로 시작했다. AWS/ASOS 관측망 자동 선택은 아직 아니다. 현재 기상 캐시는 5분, 위험지수 캐시는 10분이며 자료 기준시각과 오래됨을 표시한다.

산불위험예보 endpoint는 사용자 제공 `https://apis.data.go.kr/1400377/forestPointV2`를 기준으로 구현하고 실제 응답을 확인했다. 초기 endpoint TXT가 비어 있던 문제와 이후 연결 성공을 구분한다. `analdate`는 자료 기준시각으로 표시하며 공식 발표시각과 같다고 가정하지 않는다. 최근 과거 자료가 6시간을 넘으면 오래됨으로 표시한다. 위험지수를 전파율에 그대로 곱하지 않는다.

UI에서 실황과 수동 가상 날씨를 구분한다. 기상 응답이 여러 작업·위치와 뒤섞이던 문제는 통합 검증에서 수정했다. 풍향은 바람이 불어오는 방향이고 계산 벡터는 불어가는 방향으로 변환한다. 기온은 현재 비교 실험에서 기록 변수이며 모든 입력이 전이에 직접 영향을 주는 것은 아니다.

## 공간자료 확보와 오류 정정

사용자는 첫 지역을 대구로 지정하고 앞산공원 주변을 우선 신청했다. DEM `35803.img`는 ERDAS IMG raster로 90m×90m, 261×317=82,737칸, 약 23.5×28.5km 범위다. Windows가 디스크 이미지로 탑재하려다 손상 메시지를 냈지만 raster 읽기는 정상이다. 확장자를 TIFF로 이름만 바꾸면 안 된다.

지리OneView EXE·MapPrimeViewer는 자료를 보는 프로그램이지 DEM 파일이 아니다. 서비스의 필수 설치 프로그램도 아니다.

임상도·산림입지토양도는 35803054·35803063·35803074 세 도엽의 3쌍을 받았다. SHP·DBF·PRJ·SHX 등 전체 묶음을 함께 보존한다. '2025년 제공 임상도'에 2018·2024 갱신 속성이 있어 모두 2025년 현장 조사라고 보고하지 않는다. 임도망도 신청 의향과 실제 확보 목록은 다르며 확보한 6ZIP은 임상도·토양도다.

원본은 `runtime/external-data`, 전처리는 `runtime/spread-data`에 분리한다. 좌표계·해상도·NoData·숲 mask·자료 겹침과 hash를 확인한다. 동일 CRS·해상도·정렬의 DEM 최대 16타일 병합 지원은 추가했지만 실제 신규 타일을 받아 전체 대구 범위를 넓히지는 않았다.

현재 계산 가능한 숲은 **914셀·740.34ha·11개 연결 영역**이며 가장 큰 영역은 739셀이다. DEM 안 유효 숲 격자 비율 1.1047%는 '대구 산림의 1.1047%를 정확히 예측'한다는 뜻이 아니다. 임상도 3개를 적용해도 행정구역 전체를 덮지 않는다. 앞산·두류공원 전체의 실제 확산을 재현했다고 주장하지 않는다.

## 확산 모델

1. 원형: 기본 전파율로 반경을 늘리는 단순 기하 기준선.
2. 풍향 타원: 풍속·풍향으로 방향성을 준 기하 기준선.
3. 확률 CA: 이웃 8방향에 바람·경사·숲 유형·습도·강수 가정을 적용한 점화 전이. 반복 실행으로 조건부 연소 빈도를 계산한다.

기본 전파율 6m/모델분, 연소 지속 8모델분, 침엽 1.20·활엽 0.90·혼효 1.05 등의 계수는 실측 보정값이 아니다. 원본 90m 격자를 작은 칸으로 나눈다고 실제 측량 해상도가 높아지지 않는다. 초기 계획의 10~30m 자료 확보와 현재의 90m 자료 기반 연구를 구분한다.

CA의 10·50·90% 지도는 주어진 입력·가정에서 몇 회 연소했는지의 비율이다. 실제 화재 발생 확률이나 통계적 신뢰구간이 아니다. 10·30·60모델분도 실제 피해 도달시간으로 검증되지 않았다. 수관화·비화·진압·미기상·실제 연료 수분은 반영하지 않는다. Rothermel·FARSITE·FlamMap·딥러닝 시계열 확산을 구현한 상태는 아니다.

발화점 주변 약 5km 계산창과 데이터 범위 경고를 두고, 결과가 경계에 닿으면 한계를 표시한다. `job.json`·`result.geojson`에 요청 입력·seed·자료·격자·엔진 SHA·상태·가정값을 남긴다. 서버 재시작 시 미완료 작업은 성공으로 위장하지 않고 failed로 처리한다.

고정 가상점 위도 35.81364808382724·경도 128.59225138052454, 풍속 3m/s·불어오는 방향 270°·습도 40%·강수 0·기온 20°C를 사용했다. 기본은 30모델분·seed 42·CA 30회다.

60모델분 추가 실행의 평균 모의 면적은 107.16ha였다. 동일 입력·seed의 도형 hash와 원본 IMG·ZIP 7개 hash 보존을 확인했다. 입력 반영과 재현성을 확인한 것이며 실제 산불 정확도 검증은 아니다. CA 면적이 원형보다 크다고 더 정확하지 않으며 무풍 면적이 3m/s보다 큰 경우도 있어 풍속–면적 단조성을 주장하지 않는다.

## 발화점 자동 추정과 자동 확산

현재 실사용은 수동 지도 지정이다. 코드의 homography는 화면 기준점 4개·독립 검사점 2개, 중복점 거부·프레임 hash·고정 시야 확인을 요구한다. 최대 검사 오차 50m 이하라도 산악지형 정합을 보장하지 않는다. 가정 오차는 최소 90m이며 ORB 특징 검사도 모든 PTZ·야간·가림 변화를 잡지는 못한다.

불꽃 박스의 아래 중심을 지면 근사로 쓴다. smoke 상단이나 카메라 설치 좌표를 발화점으로 쓰지 않는다. 보정 영역 밖·회전·줌·특징 부족·서로 먼 후보는 위치를 보류한다. 이는 현재 후보의 근사 지면 위치이지 최초 발화점 추적이 아니다.

자동 확산에는 보정·명시적 연구 승인·가정 오차 150m 이하·오차 원 전체가 유효 숲인 조건·최신 기상·작업 한도가 모두 필요하다. 알람당 한 작업과 근거 hash를 남긴다. 조건이 맞지 않으면 알람은 유지하고 확산만 보류한다. 실제 4대는 보정 자료가 없어 자동 위치·확산이 OFF다.

## 대피 경로와 연구 검증의 다음 조건

사람의 대피 경로는 미구현이다. 도로·등산로 연결 그래프, 통행 가능성·통제, 대피시설, 검증된 위험 도달시간이 필요하다. Naver Directions만 붙인다고 안전한 대피 경로가 되지는 않는다.

확산 검증에는 실제 사건의 발화 좌표·시각, 시간대별 관측 경계와 당시 기상이 필요하다. 사건별 보정·독립 시험을 나눠야 한다. 현재 평가 도구는 같은 사건·시각의 관측과 예측을 미터 투영으로 맞춰 IoU·포함률·면적 오차·Hausdorff 거리를 계산한다. 합성 평가 통과와 실제 화재 정확도 평가를 구분한다.
