## 탐지 개선

기본 정책을 `models/fire_policy_v2.json`으로 변경했다. v1 필터와 클래스·점수·박스 수·프레임 후보 유무는 유지하며, IoU 0.5 이상인 같은 fire 후보의 score 제곱 가중평균과 기존 박스를 0.5 비율로 혼합한다. 최소 peer score 0.2 및 기존 score의 0.5 조건을 둔다. 연기는 이동·재분류하지 않는다. v1 정책과 가중치 원본은 유지한다. `EMBER_POLICY_PATH`로 v1을 지정하면 rollback 가능하다.

validation 3,445장의 기존 CPU 640 예측 캐시와 label SHA를 대조했다. 18개 위치 보정 조건을 파일명 hash 기반 개발 구간에서 선택한 뒤 내부 audit 구간의 TP·FP·배경 오탐 이미지·전체 미탐 이미지를 확인했다. 기존 validation을 재사용했으므로 audit 역시 새로운 독립 검증이 아니다.

- fire v1: TP 1,516 / FP 738 / FN 638.
- fire v2: TP 1,526 / FP 728 / FN 628. Precision 67.70%, recall 70.84%.
- fire 내부 audit TP 580→583, FP 281→278. 전체 불꽃 이미지 미탐 102→99, 불꽃 없는 이미지의 잘못된 후보 34장은 동일.
- smoke는 기존 TP 1,512 / FP 448 / FN 377 그대로다. 개발 후보는 전체 박스 TP가 2 늘었지만 audit의 전체 미탐 이미지 105→106으로 증가해 채택하지 않았다.
- IoU 0.5 고정 박스 평가이며 공식 test mAP나 실제 사건 recall이 아니다. 70epoch 모델을 재학습하지 않았다.

16개 validation 이미지×2회 CPU·4 threads의 decode/추론/후처리/표시 JPEG 포함 중앙값은 v1 47.7ms, v2 46.2ms, v2 P95 56.6ms였다. 작은 표본·타이밍 변동이 있어 추론 가속이라고 단정하지 않는다. 네트워크·샘플 간격·시간 게이트를 포함한 사건 탐지 지연은 아니다.

## 확산 개선

엔진 `research-ca-v1.3-sparse-equivalent`. 전이 확률 0인 숲 외부 간선은 희소 인덱스로 건너뛰고 조밀한 격자는 기존 slicing 경로를 유지한다. RNG 순서·전체 추첨 크기·확률/반올림·모델 계수는 바꾸지 않았다. 기존/신규 전체 GeoJSON 도형과 면적의 동일성, 4밀도×3seed의 격자 출력 bitwise 일치를 확인했다.

최종 유휴 상태 5회 중앙값: 30모델분 492.8→156.0ms(3.16배), 60모델분 908.6→299.0ms(3.04배), 각 30회 Monte Carlo. 실제 지형 원본 7개 hash 및 전처리 grid hash를 보존했고 13개 시나리오가 재현성·기상 민감도·누적 면적 검사를 통과했다. 이는 계산속도 개선이지 실화재 예측정확도 개선이 아니다.

## 남은 성능 과제

실제 연기·작은 불꽃 및 안개/노을/반사 등 권한 있는 정답 자료를 확보하고 카메라·사건별 독립 평가를 만든 뒤 별도 GPU 재학습이 필요하다. 현재 PC의 RTX 4060 8GB는 확인했지만 검증된 서비스 런타임은 CPU이며 임의로 CUDA 패키지를 덮어쓰지 않았다. 확산은 실제 시간별 산불 경계·기상·발화점과 연료 자료로 계수 보정·독립 검증이 필요하다. 자료 없이 성능 수치를 만들거나 현재 test에 맞춰 반복 튜닝하지 않는다.
