# 상시 CCTV 탐지·위치 추정·확산 연계 — 2026-10-09

> 최신 상태: 아래 OFF 설명은 실제 연결 시험 이전의 기록입니다. 이후 사용자가 기관의 상시 AI 분석·이미지 저장 허용을 확인했다고 답하여 ITS 4대의 시간 제한 시험을 켰습니다. 현재 간격·종료 시각·보관 조건 및 한계는 [CCTV_SOAK_TEST.md](CCTV_SOAK_TEST.md)를 기준으로 확인하세요. 실제 카메라 자동 위치/확산은 여전히 OFF입니다.

로컬 연구용 구현입니다. 제공기관의 AI 분석·증거 저장 허용은 아직 확인되지 않았으므로 실제 공공 영상의 서버 수집은 OFF입니다. 기존 API 키·모델·원본 데이터·사용자 비밀번호는 바꾸지 않았습니다.

## 1. 이번에 추가한 흐름

등록·활성화한 CCTV → 서버 작업자가 최신 HLS 조각에서 1프레임 추출 → 기존 YOLO11n → 카메라별 점수/제외 구역 → 같은 위치 지속 후보 → DB 알람·증거 → 보정된 경우 위치 근사 → 조건 통과 시 연구용 확산 작업.

- 사용자가 영상을 재생하거나 CCTV 페이지를 열어 두지 않아도 서버 작업자는 동작합니다. 웹을 닫으면 감지는 계속되지만 브라우저 팝업·소리는 전달되지 않습니다. 알람은 DB에 남아 다시 로그인해 조회합니다. 별도 SMS/푸시/자동 신고는 아닙니다.
- 공공 목록 216개를 모두 연결하는 것이 아니라 사용자가 등록하고 활성화한 카메라만 감시합니다. 현재 전역 동시 한도 4대, 카메라 등록 한도는 기존 8대입니다. 한도 초과는 미분석으로 표시하며 CPU 성능 보장 수치가 아닙니다.
- 서버·PC가 켜져 있어야 합니다. 절전/네트워크 단절/프로세스 종료/기관 중단 시 감시를 보장하지 않습니다. OS 설정은 변경하지 않았습니다.
- 설정은 DB에 저장됩니다. 재시작 시 활성 설정을 다시 읽습니다. 진행 중이던 확산 작업은 실패로 표시하고 완료로 위장하지 않습니다.
- 수집 간격 최소 2초, 기본 3초 + 대기/해석/추론 시간입니다. 모든 원본 프레임을 분석하는 방식이 아니며 짧은 화염은 놓칠 수 있습니다.
- 같은 화면 위치(IoU 0.2 이상)의 불꽃 후보를 최근 5회 중 3회, 최소 6초 확인합니다. 기본 재알람 간격 30초. 이 규칙은 실화재 검증된 경보 기준이 아닙니다.
- 새 프레임·조각이 없거나 동일 프레임이 반복되면 다시 추론하지 않습니다. 30초 이상 정체는 경고, 통신/디코딩/추론 실패는 15~300초 지수 대기로 표시합니다. 잘못된 입력·오류를 정상 감시로 취급하지 않습니다.
- HLS MPEG-TS만 지원합니다. MP4, 암호화/DRM, fMP4, byte-range, 종료된 재생 목록은 자동 수집하지 않습니다. 기관이 허용한 별도 형식 지원은 추가 구현·시험이 필요합니다.

## 2. 기관 허용 확인 방법

먼저 ITS 신청 내역의 이용 목적·조건과 연결 영상 운영기관을 확인합니다. 허용 범위가 명확하지 않으면 ITS OpenAPI Q&A/운영기관에 아래 내용을 문의하고 답변을 보관합니다. API 발급 사실만으로 승인 여부를 단정하지 않습니다. 이 문서는 법률 판단이나 허용 보증이 아닙니다.

공식 안내: https://its.go.kr/opendata/opendataList?service=cctv
UTIC: https://www.utic.go.kr/guide/utisRefCctv.do

문의 문안:

> 대학 산불 탐지 프로젝트에서 귀 기관 CCTV 일부(우선 최대 4대)의 영상을 서버가 화면 재생 여부와 무관하게 주기적으로 AI 분석하려 합니다. 원본 영상은 녹화하지 않고 메모리에서 프레임을 처리하며, 불꽃 후보 알람 발생 시 JPEG 증거 이미지를 저장하고 로그인한 연구팀 웹 화면에 표시하려 합니다. 이 용도의 무인 AI 분석·증거 이미지 저장·웹 표출이 허용되는지, 추가 신청/승인이 필요한지 알려주세요. 허용되는 카메라/기간, 동시 연결 수, HLS 영상·목록 요청 간격, 출처 표시, 개인정보 처리·보존 기간·삭제 의무, 모델 추가 학습 사용 여부도 확인 부탁드립니다.

허용 답변 없이 승인 플래그를 켜거나 기관 인증·CORS·IP 보안을 우회하지 않습니다. UTIC는 승인 대기이며 별도 키·IP·목적 확인 전 미연결입니다.

## 3. 승인 후 실제 켜는 순서

1. 허용된 카메라, 동시 접속/간격, 저장 범위를 문서로 확인합니다. 기관이 요구하는 보존·삭제 절차를 먼저 갖춥니다. 현재 자동 보존기간 삭제 기능은 없으므로 기간 조건에 맞춘 구현 전 운영 저장을 켜지 마세요.
2. 운영자가 서버 루트 .env에 EMBER_CCTV_AI_APPROVED=true와 EMBER_STREAM_ALLOWED_HOSTS=허용된_실제_영상_호스트들을 설정합니다. 와일드카드가 아닌 정확한 호스트만 사용합니다. HLS 목록·중첩 목록·영상 조각의 호스트도 각각 확인해야 합니다.
3. 로컬 서버를 재시작합니다. 비밀번호·인증키는 브라우저/VITE/공유 문서에 넣지 않습니다.
4. 공공 CCTV → 목록 조회 → 한 지점 선택 → 서버 상시 CCTV 감시에서 허용 근거와 간격을 입력합니다. 처음에는 1대만 시작해 오류·지연·기관 요청량을 확인합니다.
5. 위치 보정은 없어도 화재 후보 알람을 만들 수 있습니다. 자동 위치/확산은 보정과 추가 확인 후 별도로 켭니다.
6. 화면을 다른 페이지로 이동하고 프레임 카운터·DB 알람이 계속 증가하는지 확인합니다. 오류·영상 정체를 정상으로 오해하지 마세요.
7. 상시 감시 중지 버튼은 감시 설정을 끄고, 진행 중 추론은 설정 revision을 재검사해 중지 후 늦은 알람을 막습니다. 설정은 그대로 보존합니다.

기존 브라우저 2분 분석은 별도 테스트입니다. 서버 감시 중에는 해당 카메라의 브라우저 중복 분석을 거부합니다.

## 4. 자동 위치는 어떻게 만드는가

ITS의 공개 좌표는 설치 위치이며 공개 필드에는 방위각·기울기·줌·렌즈 정보가 없습니다. 운영기관에서 정확한 카메라 자세·렌즈·PTZ 상태를 제공하면 향후 DEM 광선 교차 방식으로 확장할 수 있으나 이번에는 구현하지 않았습니다.

이번 방식은 고정 시야의 평면에 가까운 지면을 화면과 지도에서 대응시키는 homography 근사입니다. 화면 기준점 4개와 별도 검사점 2개를 직접 지정합니다. 같은 지점을 중복해 오차를 낮춰 보이는 입력은 거부합니다. 최대 검사 오차 50m 이하, 사용자 가정 오차 최소 90m를 요구합니다. 독립 검사 통과가 실제 지형/렌즈 오차 보장은 아닙니다.

1. 선택 카메라의 감시 설정을 OFF로 저장합니다.
2. 허용된 브라우저 2분 분석으로 최근 프레임을 준비합니다.
3. 위치 보정 메뉴에서 기준 프레임 고정을 눌러 15분간 같은 이미지를 사용합니다. 프레임 해시가 입력과 다르면 보정을 거부합니다.
4. 표의 행을 선택하고 이미지에서 기준점을 클릭한 뒤 지도에서 동일한 실제 지점을 클릭합니다. 4개는 보정, 마지막 2개는 독립 검사입니다. 위성사진만으로 현장 정확도를 보장하지 마세요.
5. 고정 시야·평면 근사·렌즈 왜곡 보정 조건과 기준점의 근거를 기록하고 저장합니다.
6. 추론 시 ORB 배경 특징 매칭으로 시야가 기준과 같은지 검사합니다. 회전/줌/특징 부족/야간 변화/보정 구역 밖/멀리 떨어진 여러 후보는 위치 추정을 보류합니다. 이 검사도 모든 시야 변경을 검출한다는 보장은 없습니다.
7. 불꽃 박스 아래 중심의 지면 접점을 근사합니다. 연기 중심, 카메라 좌표, 도로 주소를 발화점으로 대신 쓰지 않습니다.

이는 현재 불꽃 후보의 지면 근사 위치이지 최초 발화지점 추적이 아닙니다. 산악 지형, 언덕/수목, 가려진 지면, 공중 불꽃, PTZ에는 그대로 적용할 수 없습니다. 그런 카메라는 위치 기능을 OFF로 두고 기관 자세 자료·3D 보정·현장 검증부터 진행합니다.

## 5. 자동 확산 안전 조건

보정된 위치가 있고 연구용 자동 실행을 확인한 카메라만 대상입니다. 가정 오차가 150m 이하이며 그 오차 원에 닿는 격자가 모두 유효한 숲 자료여야 합니다. 기상청 실황이 최신이어야 하고 최대 3개 계산 대기/진행 한도를 넘지 않아야 합니다. 조건 미충족은 알람을 삭제하지 않고 확산만 보류합니다.

알람당 작업 1개를 생성하고 알람 ID·보정 해시·위치 오차·카메라 규칙 revision·기상·자료/엔진 해시를 기록합니다. 자동 생성된 결과도 연구용이며 중심점 한 곳의 조건부 시나리오입니다. 위치 오차 전체를 반영한 확산 앙상블·실제 30분 후 피해 예측·자동 대피/신고가 아닙니다.

알람 자세히에 추정 좌표·가정 오차·보류 이유·연결 작업을 표시합니다. 발화점 지정·확산 실험으로 이동하면 기록된 추정과 연결 결과를 열 수 있고 사람이 다른 지점을 선택할 수 있습니다.

## 6. 오탐·미탐 개선

현재 best.pt와 fire_policy_v1.json은 그대로입니다. 새 서버 감시는 최소 점수(기본 .25), 제외 다각형, 공간·시간 확인을 추가하므로 원래 이미지 정책과 다른 운영 규칙입니다. 운영 알람에 합성 정책 해시, 위치 기록에 규칙·revision을 남깁니다. 낮은 점수 후보를 더 걸러 미탐이 늘 수 있으며 오탐 감소율은 아직 측정하지 않았습니다.

알람 자세히에서 실제 불꽃/오탐/판단 보류와 근거를 저장합니다. 확인/종료라는 업무 상태와 실제 정답 판정을 구분합니다. GET /api/reviews는 본인 기록만 반환합니다. 이 기록으로 데이터셋 정답을 자동 수정하거나 재학습하지 않습니다.

기존 validation 미탐 640개 중 75.3125%가 화면 면적 1% 미만, 면적 비율 중앙값 0.2367%입니다. 기존 960 실험은 no_safe_improvement 기록이므로 고해상도로 바꿨다고 개선을 주장하지 않습니다.

다음 데이터는 허용된 실제 카메라의 작은 불꽃·야간·역광·안개·차량등·햇빛 반사이며, 사람·차량 식별 정보와 이용/학습 권한을 먼저 관리합니다. 카메라/날짜/사건별로 train/validation/held-out test를 분리하고 가까운 프레임이 양쪽에 섞이지 않게 합니다. 알람 기록만으로 미탐률을 구할 수 없으므로 알람이 없던 구간도 독립적으로 정답 검토해야 합니다.

scripts/evaluate-research.py fire는 별도 정답 fire_boxes_xyxy를 준 로컬 이미지에서 박스 TP/FP/FN, precision/recall, 불꽃 없는 이미지의 오경보 수를 계산합니다. 허용 확인·분할이 없는 입력과 비어 있는 평가를 거부합니다. 영상 사건 재현율·시간당 오경보율은 추가 연속 영상 평가가 필요합니다. 테스트 결과를 보고 같은 테스트에 맞춰 튜닝하지 마세요.

## 7. 확산 자료 확대·검증

현재 원본은 보존했고 기존 격자도 덮어쓰지 않았습니다. 현재 90m DEM 내 계산 가능한 숲은 914셀·740.34ha·11연결 영역, 가장 큰 영역 739셀입니다. DEM 안 계산 가능한 숲 격자 비율은 1.1047%이며 대구 산림 전체 커버리지 수치가 아닙니다. 보유 임상도/토양 ZIP 3종씩은 이미 모두 사용한 상태입니다.

전처리 도구는 동일 좌표계·해상도·정렬의 DEM .img/.tif/.tiff 최대 16타일을 결합하도록 확장했습니다. 해상도 혼합·잘못된 정렬·과대 격자는 거부합니다. 추가 DEM과 임상도를 실제로 받아야 범위가 넓어집니다. 이번에는 새 원본을 받거나 기존 자료를 재전처리하지 않았습니다. 과거 시뮬레이션의 자료 해시를 보존합니다.

실제 산불 사건의 발화 좌표/시각, 시간대별 관측 경계, 해당 시각 기상이 없으므로 실화재 오차를 계산하거나 전파율을 새로 보정할 수는 없습니다. scripts/evaluate-research.py spread에 같은 사건/시각의 관측 경계·출처와 예측 도형을 주면 미터 투영 기준 IoU, 관측 영역 포함률, 면적 오차, 경계 Hausdorff 거리를 계산합니다. 합성 예제 통과를 실제 예측 정확도로 보고하지 않습니다.

평가 manifest의 형식:

fire: split=validation 또는 held_out_test, rights_confirmed=true, items=[{image:동일폴더_상대경로, fire_boxes_xyxy:[[x1,y1,x2,y2],...]}]. 불꽃 없는 정답은 빈 배열.

spread: 같은 split/권한 필드, items=[{incident_id:사건ID, observed_at:관측시각, observation_source:출처, predicted_geometry:GeoJSON_Polygon, observed_geometry:GeoJSON_Polygon}].

## 8. 검증 범위와 운영 전 남은 것

- 합성/임시 데이터로 두 카메라의 무재생 상시 분석, 알람, 중지 확인. 실제 모델 회귀 테스트는 별도 D-Fire 예제로 확인.
- 원본 네트워크 없이 자체 생성 MPEG-TS → FFmpeg pipe → JPEG 해석 확인. 서버가 FFmpeg에 외부 URL을 직접 넘기지 않음.
- DNS 사설/메타데이터 IP 차단, 호스트 허용 목록, HTTP 리다이렉트 거부, 중첩 목록·조각도 검사. TLS는 검증된 IP로 연결하되 원래 호스트 SNI/인증서 검증을 유지.
- 영상 메모리 응답 최대 12MB, 조각 디코딩 제한 12초, 영상 네트워크 단계에 시간/크기 제한. 실서비스는 별도 미디어 작업자 컨테이너와 OS CPU/메모리 제한·패치 관리가 추가로 필요.
- 보정 시야 변경·기준점 오류·해시 불일치 보류, 합성 추정 → 임시 작업 폴더에서 실제 CPU CA 계산 → 알람별 작업 중복 방지 확인. 기상은 테스트 주입이며 실화재 검증이 아님.
- 기존 13개 확산 시나리오 재현성과 원본 7개 자료 해시 보존 확인.
- 기관 승인 전 실제 공공 영상 무인 수집/추정/오탐률 평가 없음. UTIC, 물리 휴대폰, 장시간 부하/장애, AWS/Docker 실운영, 산악 3D 위치·실화재 보정은 미완료.
- 소스 백업: runtime/monitor-backup-bdd309e2. 모델·정책 해시는 그대로이며 실제 .env는 변경하지 않았습니다.
