# UTIC 대구 연결 시험 — 2026-10-14

## 이번 범위

공공 CCTV 화면에 ITS·UTIC 선택을 추가했다. UTIC는 대구 좌표 목록·지도·선택 HTTPS HLS 재생(최대 60초)·서버 프레임 1장 확인을 지원한다. 기존 ITS 상시 감시와 분리돼 있다. **UTIC 상시 AI 분석·화재 알람·증거 파일 저장은 이번 단계에서 켜지 않는다.** 기관별 이용 목적·저장 허용을 별도로 확인해야 한다.

## 설정

서버 루트 `.env`에 `UTIC_API_KEY`를 설정한다. `VITE_` 변수·프론트 코드·Git·로그에 키를 넣지 않는다. 키가 승인된 출발지 공인 IP에서 실행해야 한다. PC 공인 IP 변경이나 AWS 이전 시 등록 조건을 재확인한다.

좌표 원본은 기본 `runtime/external-data/cctv/OpenDataCCTV.xlsx`다. 다른 위치는 `UTIC_CATALOG_PATH`로 지정한다. `.xlsx` 원본을 수정하지 않고 읽는다. 받은 원본은 14,606개 ID, 대구교통정보센터 177개이며 위도 범위가 잘못된 2행이 있었다. 다운로드 시점의 전체 목록에는 ITS 고속도로·국도도 있으므로 중복 관제하지 않고 대구 센터만 선택한다.

## 사용

1. `scripts/start-local.ps1`로 시작하고 기존 계정으로 로그인한다.
2. 공공 CCTV → UTIC 대구 도시 CCTV → UTIC 대구 목록 조회.
3. 이름 또는 지도에서 지점을 선택한다. 선택만으로 영상을 연결하지 않는다.
4. `UTIC 영상 재생 · 최대 60초`는 선택한 한 대를 재생한다. 60초·숨긴 탭·페이지 이동에서 중지하고 자동 갱신하지 않는다.
5. `서버 프레임 1장 확인`은 기존 pinned-IP HLS·pipe-only FFmpeg 디코더로 한 장만 메모리에서 읽어 화면에 표시한다. YOLO·알람·증거 저장·카메라 등록을 호출하지 않는다. 정지 화면을 실시간 연속 영상으로 표시하지 않는다.

목록은 24시간 캐시하며 실패·강제 갱신은 최소 60초 간격이다. 개별 재생 정보와 프레임 재시험에도 카메라별 최소 60초 간격을 적용한다. 전체 CCTV 메타데이터·영상을 순회하지 않는다.

## 공식 연결 절차·안전 경계

공식 인증 목록 → 목록의 CCTV ID 확인 → 같은 인증 세션의 공식 단일 카메라 정보 → 공식 개방데이터 플레이어 → 대구 literal `videoSrc` 순서다. 실행 환경에 cookie·Referer가 필요하며 키·세션·메타데이터의 비밀번호는 서버 메모리에만 둔다. HTML·JavaScript를 실행하거나 임의 URL을 받지 않는다.

대구 공급자의 `https://carcctv.daegu.go.kr/liveN/_definst_/chN.stream/playlist.m3u8`만 지원한다. 정확한 호스트·HTTPS·포트·경로·query 없음·원본 목록 ID를 검증한다. 공식 포맷·방식이 바뀌거나 지원되지 않는 지점은 실패 상태로 표시한다. HLS 중첩 URL의 공개 IP·DNS pinning·크기·시간 제한과 디코더 pipe 제한을 유지한다. TLS/IP/인증을 우회하지 않는다.

브라우저 재생과 서버 프레임 수신은 별개다. CORS·다른 사용자 IP·기관 중단 때문에 하나만 성공할 수 있다. 화면이 잘 보인다는 이유로 상시 AI 분석 허용이나 현장 정확도를 주장하지 않는다.

## 이번 확인과 다음 단계

초기 실제 연결 확인: 가창삼거리 `E100002`, 위도 35.801472·경도 128.622411, 공식 HTTPS HLS. 기존 서비스 수집기에서 1080×720 JPEG 한 장을 디코딩했고 영상 HTTP 요청은 3회였다. 원본 프레임은 파일로 저장하지 않았다.

자동 테스트와 서비스 API 재검사 결과는 작업 완료 안내에 별도로 남긴다. 기존 학습·ITS·계정 DB는 바꾸지 않는다. 자동 발화점·확산은 보정 없이 켜지 않는다. UTIC AI 분석·증거 저장 목적 승인과 접속·보관 조건이 확인된 뒤, 단일 카메라의 시간제 분석을 다음 단계로 진행한다.
