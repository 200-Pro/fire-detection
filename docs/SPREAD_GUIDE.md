# 탐지 → 연구용 산불 확산 시뮬레이션 사용 안내

작성일: 2026-10-08. 프로젝트: `D:\fire-dettection`. 현재 범위는 로컬 데모이며 AWS 배포·실제 산불 정확도 검증 완료가 아닙니다.

## 1. 지금 할 수 있는 것

기존 YOLO11n 불꽃 후보 탐지·웹 알람을 유지하면서, 직접 선택한 발화점에서 기상·지형·숲 조건별 확산 형태를 비교합니다. 계산은 FastAPI 서버의 별도 CPU 프로세스에서 하며 Colab이나 새 YOLO 학습은 필요하지 않습니다. YOLO는 이미지 탐지, 확산 모듈은 지도상의 연구용 계산입니다.

1. `http://localhost:5173`에 본인이 설정한 계정으로 로그인합니다.
2. 왼쪽 `확산 시뮬레이션`을 누릅니다.
3. 첫 실험은 `검증된 숲 격자 지점으로 초기화`를 누릅니다. 지정점은 약 위도 35.81365, 경도 128.59225의 가상 발화점입니다.
4. `수동 가상 기상` 또는 `기상청 최신 실황`을 선택합니다. 수동 입력은 실제 관측이 아닙니다. 실황은 조회 버튼으로 확인할 수 있고, 실행할 때 다시 유효성을 검사합니다.
5. 원형/풍향 타원/CA 모델, 10/30/60 모델분, CA 반복 횟수와 seed를 정합니다.
6. 연구용 가상 발화점 확인란을 체크하고 실행합니다.
7. 완료 후 시간 버튼으로 영역을 비교하고, PNG 또는 입력·결과 GeoJSON을 저장합니다. 입력을 바꿔도 이미 저장된 결과는 바뀌지 않으므로 새 계산을 실행해야 합니다.

알람에서 시작하려면 `알람 기록 → 자세히 → 발화점 지정·확산 실험`을 누릅니다. 연결은 알람 ID를 함께 기록하는 기능입니다. **영상의 불꽃 위치를 실제 위경도로 알아낸 것이 아니며, '확인됨'은 담당자 처리 상태이지 실제 화재 확정이 아닙니다.**

## 2. 지도 자료와 계산 범위

실제 읽은 원본은 DEM `35803.img`, 임상도·토양도 각각 `35803054/35803063/35803074`의 ZIP입니다. 실행 전 원본 해시를 기록했고 이후 같은 해시를 확인했습니다. ZIP·IMG 원본에는 쓰지 않습니다.

- DEM: EPSG:5179, 90m 격자, 317×261. 90m 한 셀은 0.81ha입니다. 화면 확대가 자료 해상도를 높여 주지 않습니다.
- 임상도 319개 영역, 토양도 170개 영역. 겹치는 유효한 숲 격자는 914개입니다.
- 대구 전체를 덮지 않으며 자료 사이 빈 구간도 있습니다. **회색/자료 밖은 미확인이지 안전 지역이 아닙니다.** 숲 코드·DEM이 없는 셀은 이번 계산에서 제외됩니다.
- 임상도의 갱신년도는 여러 해가 섞여 있습니다. '2025년 파일'이 모든 폴리곤의 2025년 현장 상태를 의미하지 않습니다.
- 토양도는 포함 여부만 기록합니다. 실시간 연료 수분이나 검증된 전파 계수로 사용하지 않습니다.
- 외부 지도 타일·지도 API·CDN 없이 로컬 지형 높이대와 숲 폴리곤을 표시합니다. 도로·주소 검색 지도는 아닙니다.

## 3. 기상·위험지수는 각각 무엇인가

기상청은 단기예보 조회서비스의 **초단기실황 `getUltraSrtNcst`**를 사용합니다. 풍향·풍속·습도·강수를 확산 가정에 적용하며 기온은 기록만 합니다. 현재는 시간에 따라 변하는 예보를 적용하지 않고 실행 시점의 한 기상 조건을 전체 계산 동안 고정합니다.

- WGS84 좌표를 기상청 5km 격자로 변환합니다. 산림 안 미기상 측정값은 아닙니다.
- 관측 기준시각, 조회시각, 경과시간을 기록합니다. 실황은 120분 이내 유효성 기준을 사용하며 오래되거나 연결이 실패하면 실황 실행을 막습니다.
- 자료가 없을 때 수동 값을 실황처럼 자동 대체하지 않습니다. 수동 모드로 직접 전환해야 합니다.
- 풍향은 '불어오는 방향'입니다. 270° 서풍은 동쪽으로 향합니다.

국립산림과학원은 `forestPointV2/forestPointListSidoSearchV2`에 `localAreas=27`로 대구 시도 자료를 조회합니다. 평균·최소·최대 위험지수와 이후 시각 자료를 **별도 참고 정보**로 표시합니다. 위험지수를 화재 확률이나 확산 속도로 변환하지 않습니다. `analdate`는 자료 기준시각으로 표시하며 API에서 공식 발표시각을 별도로 제공받지 않았습니다. 6시간을 초과한 최근 과거 자료에는 오래된 자료 표시를 합니다. 기상청은 5분, 위험지수는 10분 서버 캐시를 사용합니다.

키는 이미 서버 `.env`에 보관된 `KMA_SERVICE_KEY`, `NIFOS_SERVICE_KEY`를 사용합니다. 브라우저로 키를 보내거나 VITE_ 변수에 넣지 않습니다. 키·비밀번호·.env를 팀 공유 자료에 넣지 마세요.

## 4. 모델과 색상 읽는 법

- 원형: 기본 전파율로 반경을 늘리는 단순 기하 기준선입니다.
- 풍향 타원: 풍속·풍향으로 방향성이 있는 기하 기준선입니다.
- CA: 숲 격자의 이웃 8방향에 바람·경사·숲 유형·습도/강수 가정을 적용하는 확률적 셀 전이입니다. seed가 같으면 같은 입력/버전에서 재현됩니다.
- CA 색은 10·50·90% 이상 반복 실행에서 연소한 셀의 중첩입니다. **실제 산불이 날 확률이나 통계적 신뢰구간이 아닙니다.**
- 평균 모의 연소면적은 반복 실행의 평균입니다. 화면의 가장 바깥 색 영역 면적과 같지 않습니다.
- 10/30/60분은 **보정되지 않은 모델 시간**입니다. '실제 30분 후 이곳에 불이 도착한다'고 보고하면 안 됩니다.

기본 전파율 6m/모델분, 셀 연소 지속 8모델분, 숲 가정 계수(침엽수 1.20, 활엽수 0.90, 혼효림 1.05)는 실측 보정값이 아닙니다. CA와 기하 기준선의 면적 차이를 'CA가 정확하다'는 근거로 사용할 수 없습니다. 수관화·비화·진압·미기상·실제 연료 수분은 반영되지 않습니다. 계산 창은 발화점 주변 약 5km이며 결과가 창 경계에 닿으면 경고합니다.

## 5. 팀 비교 실험

같은 발화점, seed 42, 30모델분, CA 30회에서 다음을 비교합니다. 먼저 위치·자료 해시·기본 전파율을 고정하고 한 변수씩 바꾸세요. 아래는 소프트웨어 동작 점검 결과이지 실제 예측 성능이 아닙니다.

| 실험 | 입력 | 평균 모의 연소면적 |
| --- | --- | ---: |
| 원형 기준선 | 기본 풍속 3m/s·습도 40%·강수 0 | 10.53ha |
| 타원 기준선 | 같은 입력 | 14.58ha |
| CA | 같은 입력 | 49.44ha |
| CA 건조·강풍 복합 실험 | 풍속 6m/s·습도 20%·강수 0 | 88.18ha |
| CA 습윤·강수 복합 실험 | 풍속 3m/s·습도 80%·강수 5mm | 1.57ha |

복합 실험은 두 입력이 함께 바뀌므로 개별 변수 효과를 분리한 실험은 아닙니다. 추가로 풍속·풍향·습도·강수를 하나씩만 바꾼 실험과 60모델분 실행까지 완료했습니다. 전체 13개 실행의 입력·결과·주의점은 [비교 실험 보고서](SPREAD_EXPERIMENTS.md), 시연 순서는 [팀 안내](TEAM_DEMO.md)를 참고하세요. 동일 CA 입력 재실행은 결과 도형 SHA가 일치했습니다. 재현 명령과 기록:

```powershell
Set-Location "D:\fire-dettection"
& ".\.venv\Scripts\python.exe" ".\scripts\check-spread.py" --report ".\runtime\spread-verification-final.json"
```

## 6. 파일·서버 구조

- `backend/app/spread/`: 기상·위험지수·GIS 전처리·확산 엔진·작업 API.
- `frontend/src/SpreadPage.tsx`: 설정, 로컬 지도, 결과/이력, 다운로드 화면.
- `runtime/external-data/`: 다운로드한 원본. 삭제·수정하지 않습니다.
- `runtime/spread-data/`: 재생성 가능한 격자·GeoJSON·manifest. 격자 해시가 다르면 계산을 거부합니다.
- `runtime/spread-jobs/<id>/`: job.json, result.geojson. 입력·상태·seed·자료/엔진 해시·가정 파라미터를 보존합니다.
- 로그인/카메라/알람 DB와 탐지 모델은 기존 것 그대로입니다. 확산은 전용 CPU 작업자 1개, 최대 대기/진행 작업 3개입니다. 서버 재시작 시 미완료 작업은 실패로 표시하고 자동 완료로 위장하지 않습니다.

원본 자료를 추가하거나 바꿨을 때만, 계산이 진행 중이지 않은 상태에서 전처리를 다시 합니다.

```powershell
& "D:\fire-dettection\.venv\Scripts\python.exe" "D:\fire-dettection\scripts\prepare-spread-data.py"
```

서버 시작은 기존 `scripts/start-local.ps1`, 중지는 `scripts/stop-local.ps1`을 사용합니다. 이번 확인은 PC localhost에서 했습니다. Android/iPhone 실기기 카메라·LAN HTTPS·권한은 `PHONE_TEST.md`의 별도 사용자 확인이 필요합니다. Docker 설정에는 전처리 자료 읽기 전용 마운트, 작업 결과 볼륨, 서버 API 키 전달을 추가했으나 Docker/AWS 실제 배포는 하지 않았습니다.

## 7. 팀원이 준비할 것과 다음 연구

이 PC에서 화면만 함께 확인하면 로그인 외 추가 설치는 없습니다. 다른 PC에서 서버를 실행하려면 프로젝트 코드, 검증된 모델/정책, 전처리 자료 사본, Python 가상환경/프론트엔드 패키지가 필요합니다. 가상환경·node_modules는 복사하지 말고 setup-local.ps1로 각 PC에 설치합니다. 실제 API 조회는 각 서버의 비공개 .env를 별도 설정합니다. 수동 시나리오는 키 없이 가능합니다.

다음 연구는 실화재 발화점·시각·시간대별 경계 자료로 전파율/연료 가정을 보정하고, 학습/보정에 쓰지 않은 화재 사건으로 검증하는 것입니다. 임상도 지역 확대와 고해상도 DEM, 실제 연료 모델, 시간별 기상과 불확실성도 필요합니다. 대피 경로는 도로·등산로 연결 그래프, 통제/통행 조건, 대피 장소, 검증된 위험 도달시간이 추가로 필요하며 **이번 버전은 안내하지 않습니다**.

기술 근거: [기상청 서비스](https://www.data.go.kr/data/15084084/openapi.do), [MapLibre 공식 문서](https://maplibre.org/maplibre-gl-js/docs/). NIFOS 요청주소는 사용자가 제공한 공식 서비스 URL과 요청 항목 캡처를 바탕으로 실제 응답을 확인했습니다.
