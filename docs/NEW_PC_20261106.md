# 새 PC 이전 준비·검증 — 2026-11-06

## 적용 내용

- 설치 안내의 기본 정책을 v2로 정정하고 비공개 파일·초기 계정·등록 IP·Naver Web URL·휴대폰 HTTPS 준비를 정리했다.
- `scripts/check-local.py`는 오프라인에서 Python·Node·프론트 의존성·`.env`·실제 모델/정책 호환·예제 파일·GIS grid SHA·UTIC 좌표 목록을 검사한다. 키는 설정 유무만 출력하고 값이나 영상 URL은 출력하지 않는다. `--require-spread`, `--require-utic`은 해당 기능의 준비 누락을 오류로 처리한다.
- 시작 스크립트는 사전 점검 실패 시 서버 프로세스를 띄우지 않는다. 설치 스크립트는 Node/npm·Python Launcher·Python 버전·pip 실패를 확인한다.
- Dockerfile/Compose도 v2 정책을 쓰며 UTIC 서버 키·비공개 좌표 디렉터리 설정을 연결했다. `docker compose config --quiet` 검증만 수행했고 컨테이너 빌드/통합 운영 완료는 아니다.
- 새 프론트 설치에서 발견한 npm 감사 경고에 따라 Vite 8.3.2 → 8.3.6, Vitest 4.1.11 → 4.1.12 패치를 고정하고 lockfile을 갱신했다. 패키지의 공개 수정 안내와 감사 결과를 확인했다. 애플리케이션 기능의 대규모 라이브러리 전환은 하지 않았다.

## 실제 검증과 경계

- 기존 개발 PC: Python 3.12.10, Node 24.18.0, npm 11.16.0. 이전 코드의 전체 백엔드 116개·프론트 35개 및 빌드 성공을 재확인했다.
- 별도 임시 경로에 소스를 새 clone했다. 비공개 파일·설정·프론트 의존성이 없는 상태에서 사전 점검이 실패하는 것을 확인했다.
- 모델·전처리 GIS·예제 사본을 임시 경로에 전달하고 실제 npm 의존성을 새 설치했다. 새 환경 파일과 새 SQLite DB를 사용했고 운영 DB·실제 API 키는 복사하지 않았다.
- 별도 경로에서 Alembic 마이그레이션과 실제 모델→웹/발행 프레임→알람→GIS 확산 통합검사 1개를 통과했다. 기존 Python venv의 패키지는 재사용했으므로 새 Windows PC에서 Python 의존성 전체를 설치한 검증은 아니다.
- 패치된 프론트 35개 검사 및 TypeScript·Vite 빌드, npm audit 취약점 0건을 확인했다. npm 감사 결과는 당시 등록된 권고 기준이며 모든 취약점이 없다는 보장은 아니다.
- 원본 경로의 실제 모델·GIS·UTIC 좌표를 사용하는 사전 점검을 통과했다. API의 실제 사용 성공은 새 PC의 키·출발지 IP·제공기관·지도 origin 조건을 별도 확인해야 한다.
- PowerShell 설치·시작 스크립트 문법과 Compose 설정을 검사했다. GUI 조작·휴대폰 신뢰 설정·다른 PC의 방화벽·장시간 CCTV 연결·지도 전환 오류는 이번 검증에 포함하지 않았다.

## 팀원 실행

[GITHUB_SETUP.md](GITHUB_SETUP.md)의 명령과 비공개 전달 표를 따른다. 기본 탐지용 모델은 필수이고, GIS/UTIC/예제는 사용하는 기능에 맞게 준비한다. 같은 학습 데이터 전체 ZIP을 옮길 필요는 없다. `.venv`, `node_modules`, 기존 PC 인증서는 복사하지 않는다. 기존 계정·카메라·알람 이력은 자동 복원되지 않는다.
