## 실제 연결 중 발견한 문제

- 공식 HTTPS 영상 URL이 동일 호스트 HTTPS 8082로 302 이동: 최대 2회 동일 호스트 이동만 허용하고 각 단계의 URL/호스트/공개 IP/TLS를 검사합니다. HTTPS에서 HTTP로 하향하거나 다른 호스트로 이동하지 않습니다.
- 이동 후 상대 영상 조각은 최종 재생 목록 주소를 기준으로 해석합니다.
- 처음 승인된 재생 목록 대신 입구 주소를 매번 다시 열 때 403 응답을 관측했습니다. 통상적인 HLS 재생처럼 실제 활성 media playlist를 메모리에서 재사용하도록 수정했습니다. 403의 기관 내부 사유는 확인되지 않았으며 인증·IP·TLS·DRM 제한을 우회하지 않습니다.
- 초기 시험 집계에는 위 수정 전 오류와 개발 중 재시작 공백이 포함됩니다. 그 결과를 "무중단 1시간 성공"으로 발표하면 안 됩니다. 수정 후 연속 구간 및 후속 독립 시험을 따로 확인해야 합니다.
- API 목록 호출 수와 영상 HTTP 요청 수는 별개입니다. 최초 연결은 이동/중첩 목록 때문에 4회였고 이후 구성에 따라 달라집니다. 실제 집계로 월 트래픽을 추정해야 합니다.
