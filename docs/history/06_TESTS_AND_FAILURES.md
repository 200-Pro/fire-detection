- 읽기 전용 약 3분 진단: 4대 각 18프레임, 총 72프레임, 오류 0. 원본 영상·프레임은 저장하지 않았다.

- 실제 서비스 2분 시험: 4대 각 12프레임, **총 48개 YOLO 분석·오류 0**. 평균 간격 약 10.36~10.42초, 카메라별 영상 HTTP 요청 26회. 영상 플레이어를 보지 않는 설정 페이지에서도 분석이 누적됐고 4대 자동 종료를 확인했다.

## API 호출과 영상 요청을 구분

ITS 인증키 목록 API와 HLS 영상 HTTP 요청은 별도다. 같은 조건의 24시간 캐시를 공유하고 하루 1~4조건을 조회한다면 월 30~120회 목록 조회라는 예시가 된다. 전국 조건·실패·재시작이면 늘어난다.

1,000대·30일·24시간·10초 샘플, 샘플마다 playlist 1회+조각 1회라는 가정에서는 월 **518,400,000회 영상 HTTP 요청**이다. 인증키 사용량과 같은 집계가 아니며 HLS 구성·대기·업데이트·전송 bytes에 따라 달라진다. 영상을 계속 받고 AI만 느리게 돌리면 영상 요청은 줄지 않는다. 이번 2분 시험의 카메라별 26회 같은 계측값으로 재산정해야 한다.

사용자가 공유한 ITS Q&A의 월 1,000건 초기 한도·증설 사유·출처 표시·AWS 출발지 IP 포트 허용 절차는 참고자료다. 현재 키의 조건이나 본 프로젝트 개별 승인서로 치환하지 않는다. 서울 리전이어도 해외 IP로 분류돼 차단될 수 있다는 안내가 있었고 실제 AWS 배포는 하지 않았다.

## 증거 보관과 정리

새 시간제 시험의 알람 JPEG에 개별 만료를 기록한다. 보관 설정은 1~24시간이며 기존 1시간 시험은 24시간, 2분 재시험 버튼은 1시간 보관이다. 서버가 켜져 있을 때 약 60초마다 처리하므로 OFF 기간의 정시 삭제는 보장하지 않는다. 기존 사진·DB·ZIP·모델을 일괄 삭제하지 않는다. 기관 조건이 더 엄격하면 그 조건을 따른다.

S3 버전·lifecycle, 얼굴·번호판 비식별화, 알람 메타데이터 보존·삭제 규칙은 미완료다. 허용 근거는 사용자 확인 진술로 기록했다. 기관 담당자의 실제 안내 원문은 팀이 비공개로 보관해야 한다.

## 남은 작업과 합격 기준

1. **장시간 연결:** 수정 코드로 1대→4대 독립 시간제 시험. 성공률·P50/P95·최대 간격·403·요청/bytes·복구·deadline을 검토한다. completed는 안정성 pass가 아니다.
2. **현장 탐지:** 주야간·안개·노을·헤드라이트·반사·작은 불꽃의 권한 있는 연속 자료와 정답. 사건 recall·오경보/시간·탐지 지연을 측정하고 알람 없는 구간도 검토한다.
3. **위치:** 고정 시야 기준점·독립 검사점·렌즈·산악 3D 자료. 보정 전 실제 4대 자동 위치는 OFF를 유지한다.
4. **확산:** 범위·해상도 확대, 실제 사건 경계·시각·기상, 분리 보정·독립 평가. 모의 면적을 정확도로 제출하지 않는다.
5. **사용성:** 실제 Android/iPhone HTTPS·권한·플레이어, 여러 브라우저, 사용자 5~8명 시험. 개인 사진 시연을 통제 시험으로 대체하지 않는다.
6. **배포·스케일:** Docker·PostgreSQL·S3 실행, 백업 복구·TLS·기관 출발지 IP·부하·worker 격리·분산 설계.
7. **모델:** 카메라별 hard-negative·작은 불꽃 추가 학습과 ONNX 정합 평가. held-out test에 맞춘 반복 튜닝은 금지한다.

HLS 동적 import로 초기 JS는 약 880KB→305KB, HLS는 약 575KB 별도 chunk로 분리했다. 지도 chunk 약 1,060KB 경고와 의존성 deprecation은 남아 있다.
