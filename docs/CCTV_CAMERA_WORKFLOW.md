# CCTV 화면과 서버 감시 개선 (2026-10-10)

## 사용 방법

1. `scripts/start-local.ps1 -NoBrowser`로 서버를 시작하고 `http://localhost:5173/`에 접속한다. 시작 스크립트는 Alembic 스키마 이행을 먼저 실행한다. 실제 계정 인증은 유지한다.
   서버 재시작에 따른 일시적 연결 실패를 로그인 만료로 오인하지 않는다. 3초 간격으로 세션 확인을 재시도하고 서버 복구 시 기존 세션으로 복귀한다. 실제 401/세션 만료는 정상 로그인 절차를 유지한다. 계정 비밀번호를 소스·브라우저 저장소에 저장하지 않는다.
2. 공공 CCTV에서 기관 허용 근거, 분석 간격, 시험 시간을 설정하고 서버 감시를 시작한다. 기존 설정은 `2분 재시험 · 기존 허용 설정`으로 10초 간격의 짧은 시험을 시작할 수 있다. 이 버튼은 자동 확산을 끄고 새 시험 증거의 보관 기간을 1시간으로 설정한다.
3. 서버 감시가 켜진 카메라는 화면 재생·페이지 이동과 관계없이 서버가 프레임을 받아 YOLO로 분석한다. 카메라 활성화만으로 서버 시험이 시작되지는 않는다. 서버 종료·PC 절전·시험 시간 종료 시 분석도 중지된다.
4. 불꽃 또는 연기 후보가 지속되면 알람이 생긴다. 이름·설치 위치·증거를 확인하고 `카메라 화면 보기`를 누르면 카메라 관리의 해당 카메라 창이 열린다. ITS 영상은 `실시간 영상 재생`을 눌러 선택한 한 대만 재생한다. 창 닫기·재생 중지는 브라우저 영상 연결을 정리하며 서버 감시를 중지하지 않는다.
5. 카메라 관리의 `새 감지 알람 시 해당 카메라 화면 자동 열기`는 이 브라우저의 선택 사항이다. 기본 OFF이다. ON이면 새 실제 카메라 알람의 화면을 열되, 이미 다른 카메라 창을 확인 중일 때 강제로 바꾸지 않는다. 예제 알람은 자동으로 열지 않는다.
6. 사용하지 않는 카메라의 `목록에서 제거`를 누르고 확인한다. 전송·연결 코드는 폐기하고 상시 감시를 해제하지만 과거 알람·증거는 유지한다. `제거된 카메라 보기`에서 복원할 수 있다. 복원은 비활성 상태이며 새 연결 코드가 필요하다. 과거 증거에는 기존 보관 만료 정책이 계속 적용된다.

## 정상 감시와 화면의 구분

- 카메라 카드는 최신 분석 정지 프레임이다. 수천 개의 실시간 스트림을 동시에 재생하는 화면이 아니다.
- 수신이 오래되거나 오류이면 정상 수신 상태로 표시하지 않는다. 최근 프레임은 메모리에 최대 5분만 유지하며 과거 프레임으로 표시한다. 서버 재시작 후 이 프레임은 없다.
- 연결 오류는 제공기관 HTTP 상태와 목록/영상 조각 단계로 구분해 기록한다. URL·인증 쿼리는 오류 메시지에 넣지 않는다.
- 401/403/429는 최소 60초 대기하며 `Retry-After`를 존중한다. TLS 검증·공개 IP 검사·호스트 허용 목록은 유지한다. 제한된 동일 호스트 이동만 허용하며 권한 오류를 우회하지 않는다.
- 새 서버 워커는 이전 재생 세션 캐시를 재사용하지 않는다. 실행 중에는 정상 허가된 media playlist를 재사용해 최초 티켓을 반복해서 열지 않는다.

## 알람 기준 및 한계

- 불꽃은 기존 모델 후처리·카메라별 점수 하한·제외 구역을 적용한다. 연기는 점수 0.5 이상을 후보로 사용한다. 연기도 제외 구역을 적용한다.
- 서버 감시는 기본 3/5회·최소 6초, 같은 위치 박스 IoU 0.2 이상 확인 규칙을 적용한다. 연기 기준은 현장 정확도를 검증한 최적값이 아니라 초기 연구 기준이다.
- 동시에 불꽃·연기 조건이 만족되면 불꽃 알람을 우선해 한 건 생성한다. 연결 실패·장시간 새 프레임 없음은 시간 확인 상태를 초기화한다.
- 모델/규칙 해시와 실제 후보 종류를 알람에 남긴다. 기존 알람은 불꽃으로 이행한다.
- 카메라 설치 좌표는 발화점이 아니다. 화면–지도 보정 없는 자동 발화점/확산은 켜지 않는다.
- 현재 단일 프로세스·CPU·동시 감시 한도 4대이다. 수천 대 확장 완료나 실제 화재 탐지율 보장이 아니다.

- 실제 ITS 안심·달성·다부·도동대교: 약 3분의 읽기 전용 진단에서 각 18프레임, 총 72프레임 정상 디코딩, 오류 0회. 원본 영상과 이미지는 저장하지 않았다.
- 실제 카메라 관리에서 안심 CCTV HLS 영상이 재생되는 것을 화면으로 확인했다.
- 실제 서비스에서 4대의 2분 서버 분석 시험을 시작하고 영상 없는 시스템 설정 화면으로 이동했다. 각 12프레임, 총 48프레임을 YOLO로 분석했으며 오류 0회, 4대 자동 종료를 확인했다. 실제 샘플 간격 평균은 약 10.36~10.42초였다. 접속 한도 계산에서 목록 API와 HLS 목록/조각 요청은 구분해야 한다. 이 시험의 카메라별 영상 HTTP 요청은 26회였다. 기록: `runtime/cctv-check-20261010.json`.
- 백엔드 테스트는 별도 DB에서 인증·제거·복원·전송 키 폐기·기록 보존·연기 알람·미리보기 상태·HLS 안전 조건을 검증한다. 프론트 테스트는 수동/자동 카메라 열기와 제거 확인을 검증한다.
