## ADR-01 — 탐지와 확산을 분리

YOLO 출력은 픽셀 박스·클래스·후보 점수다. 이것만으로 화재 위치, 이동 방향, 미래 경계를 만들 수 없다. 확산은 위치·날씨·DEM·연료 격자·가정 계수를 입력하는 별도 계산이다. 알람 ID와 모델/규칙/자료/엔진 버전으로 둘을 연결한다. 탐지 best.pt만 바꿔도 지도 UI를 새로 만들 필요는 없지만 확산 정확도가 함께 좋아지지는 않는다.

## ADR-02 — YOLO26n 시험 후 YOLO11n 단일 기준선

초기 설치 중 최신 모델을 시험하는 비용은 작았다. 본 학습에서는 공식 도구 경로와 축적된 자료, 두 팀원의 재현 가능성을 우선했다. 같은 데이터·seed에서 모델 비교 없이 YOLO11n이 더 정확하다고 결론 내리지 않는다. 서비스에 YOLO11/26 실시간 전환 메뉴를 넣은 것도 아니다.

## ADR-03 — 라벨 원본 보존

라벨의 기하 오류를 발견했지만 정답을 모델 예측에 맞춰 바꾸지 않았다. 0면적 제거와 경계 클리핑이라는 사전 정의 규칙을 모든 분할 사본에 동일 적용했다. 라벨의 의미 정확성/같은 사건의 중복/누락은 별도 인간 검토다. 초기 '라벨 오류 없음' 기록은 범위가 좁았으므로 최신 v2 결과가 이를 정정한다.

## ADR-04 — conf만 크게 올리는 오탐 감소를 거부

사용자 우선순위는 오탐 억제였지만 불꽃을 더 놓치는 개선은 피하려 했다. conf 0.5는 FP 205로 감소하는 대신 FN 1,094로 증가했다. 채택한 추가 중복 제거+강한 후보 근처 약한 후보 규칙은 이미지 후보 유무와 전체 FN을 안전 조건으로 삼았다. 개별 박스 손실과 validation 재사용 한계는 남았다.

## ADR-05 — 모듈형 단일 서비스에서 시작

FastAPI 내부 추론·알람·스토리지·수집 인터페이스를 분리하되 처음부터 운영 복잡도가 큰 분산 서비스로 배포하지 않았다. SQLite와 로컬 파일은 로컬 demo용 선택이다. PostgreSQL/S3는 설정 가능한 경계이지 이미 실서비스에서 운영 중이라는 뜻은 아니다. 전역 카메라 4대 CPU 감시를 수천대로 늘리려면 queue·lease/sharding·공유 게이트·dedup·GPU 처리량 검증이 필요하다.

## ADR-06 — 사용자 화면과 서버 감시 독립

한 화면에 수천개의 영상을 표시할 수 없다는 요구를 반영했다. 등록·허용·활성 감시 카메라의 수집은 백엔드에서 계속되고, 프론트는 상태/알람을 표시한다. 플레이어는 선택한 한 대만 재생한다. 브라우저를 닫으면 서버 분석/DB 저장은 가능하지만 브라우저 알림·소리는 전달되지 않는다. SMS/모바일 push/119 신고는 구현하지 않았다.

## ADR-07 — 카메라 좌표를 발화점으로 쓰지 않음

공공 API의 좌표는 설치 위치다. 화면의 불꽃을 지도에 옮기려면 카메라 자세/렌즈/지형 또는 기준점 보정이 필요하다. 현재 homography는 평면 지면의 고정 시야 근사이고 최초 발화점 추적도 아니다. 실카메라 보정이 없어서 자동 위치/확산 OFF다. 연기 꼭대기 좌표를 발화점으로 치환하지 않는다.

## ADR-08 — Naver 지도는 시각화 교체

기존 MapLibre의 DEM/숲 격자 화면은 계산 확인에 유용하지만 지명·도로가 없어 사용자가 이해하기 어려웠다. Naver 배경과 주소 변환을 추가했다. Dynamic Map, Geocoding, Reverse Geocoding은 선택했지만 Static Map·Directions를 실제 확산 알고리즘으로 사용하지 않았다. 로컬 PNG 내보내기는 유지하며 Naver 타일을 무단 수집/재배포하는 기능은 제공하지 않는다.

## ADR-09 — 권한 확인과 안정 연결을 별도 처리

API 키 발급만으로 상시 AI 분석/이미지 저장 목적이 허용된다고 단정하지 않았다. 사용자 확인 전 실제 공공 감시는 OFF, 확인 후 시간 제한 시험으로 시작했다. UTIC와 ITS는 다른 기관/API다. 403을 TLS/IP/인증 우회로 해결하지 않고 제한된 redirect·캐시·backoff·진단을 보완했다. 장시간 문제의 원인은 아직 확정되지 않았다.

## ADR-10 — 카메라 삭제 대신 archive

사용하지 않는 휴대폰 카메라는 목록에서 제거하되 기존 알람/시험 기록의 연결을 보존해야 했다. soft archive는 감시를 해제하고 pairing/publisher key를 폐기한다. 복원은 비활성 상태로 시작한다. 사용자가 실제 DB 카메라를 제거할지는 화면에서 선택하며 이번 작업이 자동으로 기록을 지운 것은 아니다.

## ADR-11 — 개발 편의와 실제 인증 유지

사용자는 로그인 요청 반복을 줄이길 원했다. 실제 인증을 삭제하거나 비밀번호를 코드/localStorage에 넣는 대신, 서버 재시작 오류를 세션 만료와 구분하고 재확인을 구현했다. 자동 테스트는 별도 DB/계정을 사용한다. genuine 401/만료는 로그인 절차를 유지한다.

## 현재 의존성 기준

확인한 requirements/package 파일 기준: FastAPI 0.141.1, Uvicorn 0.52.4, SQLAlchemy 2.0.52, Alembic 1.19.2, Ultralytics 8.4.143, httpx 0.28.1, rasterio 1.5.2, pyproj 3.8.0, Shapely 2.2.0, imageio-ffmpeg 0.6.0. React/React DOM 19.3.0, TypeScript 7.0.2, Vite 8.3.2, hls.js 1.7.3, MapLibre ^6.13.0, Vitest ^4.0.0이다. 이는 이 저장소의 고정/범위 설정이며 새 프로젝트에서 임의로 최신 업그레이드하지 말고 lock과 호환성을 먼저 확인한다.

실제 PyTorch/CUDA/OS의 실험별 버전은 `environment.json`, `pip-freeze.txt`에 있다. 초기 로컬/Colab 로그가 서로 다른 버전이어도 단일 환경으로 합쳐서 기록하지 않는다.
